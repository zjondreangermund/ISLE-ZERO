# ISLE//ZERO — Roblox Studio Model Import Guide

This guide explains exactly where to place finished models so the procedural game keeps all gameplay logic but stops showing primitive placeholder blocks.

## Before importing anything

1. Stop Play/Test mode in Roblox Studio.
2. Keep Rojo connected to the `ISLE-ZERO` project.
3. In Explorer expand:
   `ReplicatedStorage > ISLEZeroAssets`
4. You should see:
   - `Structures`
   - `Nature`
   - `Creatures`
   - `Props`
   - `Tools`

Do **not** paste finished replacement models directly into `Workspace > ISLE_ZERO_WORLD`. That world is regenerated every Play session and your manual object will be deleted.

The asset folders use Rojo `$ignoreUnknownInstances`, so models you manually place inside `ISLEZeroAssets` are preserved while Rojo is connected.

---

## Method A — Creator Store / Toolbox model

1. Open `View > Toolbox` if Toolbox is not already visible.
2. Choose `Creator Store` / `3D Assets` / `Models`.
3. Insert the model you want.
4. Roblox normally inserts it into `Workspace` first.
5. In Explorer, expand that inserted model and remove any:
   - `Script`
   - `LocalScript`
   - `ModuleScript`
   The replacement system also strips executable scripts from the cloned visual, but the stored source asset should still be clean.
6. Select the complete model in Explorer.
7. Rename it to the exact ISLE//ZERO asset name listed below.
8. Drag the model in Explorer from `Workspace` into the correct `ReplicatedStorage > ISLEZeroAssets` folder.
9. Stop and Play again.

You do **not** manually position the model at every tree/camp/chest location. The game clones and positions it automatically.

---

## Method B — FBX / OBJ / glTF / Blender export

1. Stop Play mode.
2. Open Roblox Studio's `3D Importer` from the Home/Avatar/Model tools depending on your Studio layout.
3. Import the FBX/OBJ/glTF file.
4. Let Studio create the Model/MeshParts.
5. Group all pieces into one Model if the import created multiple loose objects.
6. Rename the complete Model to the exact asset name below.
7. Move it into the matching `ISLEZeroAssets` folder.
8. Set the model pivot as described below.
9. Play-test.

---

## Model pivot — very important

The model pivot should normally be at the **bottom center** of the model where it touches the ground.

Example: for a tree, put the pivot at the center of the trunk at ground level, not in the middle of the canopy.

To change it:

1. Select the Model.
2. Open the `Model` tab.
3. Use `Pivot > Edit Pivot`.
4. Move the pivot to the ground/contact point.
5. Finish/confirm the pivot edit.

If the model is still too high or buried after automatic placement, add an Attribute to the stored model:

- Name: `ISLEZeroYOffset`
- Type: Number
- Example values:
  - `2` moves it 2 studs upward.
  - `-1.5` moves it 1.5 studs downward.

Optional rotation correction:

- Name: `ISLEZeroYaw`
- Type: Number
- Value is degrees, for example `90`, `-90`, or `180`.

You add Attributes from the Properties/Attributes area while the stored model is selected.

# Current automatic replacements

## Nature folder

Place these in:
`ReplicatedStorage > ISLEZeroAssets > Nature`

Exact names:

- `JungleTree`
- `EmergentTree`
- `Palm`
- `Mangrove`

One stored `JungleTree` currently becomes the visual used for all generated JungleTree placeholders.

## Structures folder

Place in:
`ReplicatedStorage > ISLEZeroAssets > Structures`

Exact name currently wired automatically:

- `SafeTent`

The invisible generated tent/camp scaffolding remains underneath so checkpoint, rest, fire and safe-zone logic keep working.

## Props folder

Place in:
`ReplicatedStorage > ISLEZeroAssets > Props`

Exact names:

- `WorldChest` — normal outdoor/world chests.
- `CaveChest` — cave branch treasure chests.

Prompts and loot logic remain on the invisible generated placeholder while your finished chest is displayed over it.

## Creatures folder

Place in:
`ReplicatedStorage > ISLEZeroAssets > Creatures`

Cave/boss names:

- `CaveBoar`
- `SaltwaterCroc`
- `RidgeWolf`
- `BlackJaguar`
- `FeralHound`
- `IceBear`

Roaming wildlife:

- `WildBoar`
- `MarshCroc`
- `TimberWolf`
- `JungleStalker`
- `IceWolf`

The current system welds the authored creature model onto the invisible moving AI root. This means it can immediately replace the block animal body. Full bone/skeletal animations can be added as a later animation layer.

## Tools folder

`ReplicatedStorage > ISLEZeroAssets > Tools` is reserved for finished tool/weapon art. The existing weapon visuals are still generated by `AdventureToolVisuals.server.lua`; tool model auto-swap will be wired separately before relying on this folder.

# Quick first test

The easiest replacement to test is a chest or tree.

### Test a tree

1. Insert one good tree model from Creator Store.
2. Delete scripts inside it.
3. Rename it exactly `JungleTree`.
4. Set its pivot at the trunk base.
5. Drag it into:
   `ReplicatedStorage > ISLEZeroAssets > Nature`
6. Press Play.

Generated jungle-tree collision remains, but the primitive trunk/ball-canopy appearance should be hidden and your model should appear instead.

### Test a tent

1. Insert a tent model.
2. Clean scripts.
3. Rename it exactly `SafeTent`.
4. Put its pivot at ground level near the center of the tent footprint.
5. Move it into:
   `ReplicatedStorage > ISLEZeroAssets > Structures`
6. Build a camp during Play.

Your tent visual should be placed on the generated safe camp automatically.

# What should be code-built vs modeled?

Luau can generate very good modular structures such as:

- huts and cabins
- temples and ruins
- bridges
- docks
- fences
- towers
- camps
- bunkers
- modular villages
- cave layouts
- dungeon layouts

The best production approach is usually:

- **code** for layout, procedural variation, interactions, collision, loot, AI and progression;
- **MeshParts/models** for high-detail organic or sculpted visuals such as animals, realistic trees, carved rocks, detailed chests and statues.

This is why ISLE//ZERO keeps the gameplay placeholder invisibly underneath the finished visual: art can improve without rewriting the systems.
